실행 파일 조사

Chronicon.exe 를 역분석해 확인한 수치와, 확인하지 못한 것

검색 결과가 없습니다.

왜 실행 파일을 봤나

드랍 확률을 알고 싶었는데 어디에도 적혀 있지 않았습니다. 체인지로그는 「조정했다」까지만 말하고, 커뮤니티 수치는 출처가 없었습니다. 그래서 게임 실행 파일에서 직접 확인했습니다.

GameMaker YYC 네이티브 컴파일이라 data.win 에 코드 청크가 없고, 게임 로직과 상수가 전부 Chronicon.exe 안에 들어 있습니다. 도구는 exe_work/ 에 있습니다 데이터

실행 파일에서 확인한 확률

아래 수치는 Chronicon.exe를 직접 뜯어 얻은 것입니다. 패치 노트에도 게임 안에도 나오지 않는 값입니다.

왜 실행 파일인가 — data.win에는 CODE 청크가 없습니다. YYC 네이티브 컴파일이라 게임 로직과 상수가 전부 Chronicon.exe 안에 있습니다. 그래서 changelog/에 안 적힌 확률은 실행 파일을 봐야 합니다.

아이템 등급 굴림 itemRollQuality

드랍한 아이템의 등급을 정하는 함수입니다. 10만분율로 네 번 굴리고, 먼저 걸리는 쪽으로 확정합니다.

roll = irandom(100000)
  roll <    100 → 전설
roll = irandom(100000)   (단계마다 새로 굴립니다)
  roll <  1,000 → 유니크
roll = irandom(100000)
  roll < 10,000 → 희귀
roll = irandom(100000)
  roll < 60,000 → 마법부여
  그 외          → 일반
등급문턱값그 단계 확률순차 적용 최종
전설 Legendary100 / 100,0000.1%0.100%
유니크 Unique1,000 / 100,0001%0.999%
희귀 Rare10,000 / 100,00010%9.89%
마법부여 Enchanted60,000 / 100,00060%53.4%
일반 Ordinary——35.6%
이건 매직 파인드가 붙지 않은 기본값입니다. MF가 이 굴림에 어떻게 들어가는지는 확인하지 못했습니다 미확인. 실제 게임에서는 위 수치보다 좋게 나옵니다.

가방 굴림 bagDrop

등급 굴림과 똑같은 구조입니다 — 만분율로 네 번 순차 굴림.

가방문턱값그 단계순차 최종
무한한 가방 Bottomless Bag300 / 10,0003%3.00%
배낭 Backpack900 / 10,0009%8.73%
장비 가방 Gear Bag2,500 / 10,00025%22.07%
작은 가방 Satchel5,000 / 10,00050%33.10%
주머니 Pouch——33.10%

가방 아이템 ID 396~400이 함수 안에 직접 박혀 있어 locale/items와 1:1로 맞춰 확인했습니다

교차 확인 — 개발자 테스트 노트 tinka build 250930에 “작은 가방(Satchel)이 드랍되지 않고 항상 한 단계 위 가방이 대신 떨어지던 버그를 수정”이라는 항목이 있습니다. 위 표에서 작은 가방이 바로 아래 단계(주머니)와 같은 33.10%를 차지하는 구조라, 이 한 칸이 빠지면 확률이 위로 쏠린다는 게 맞아떨어집니다. 같은 노트에 “가방이 더 자주 떨어지도록”도 있으니 실제 드랍 빈도는 이 확률표와 별개로 조정됩니다 — 위 표는 어느 가방이 나오는지의 비율이지 가방 자체가 떨어질 확률이 아닙니다. 개발자

체력 · 마나 구슬은 70% 문턱입니다

몬스터가 죽을 때 도는 actorDeathDrops가 playerGetLowHealth()와 playerGetLowMana()를 부른 뒤, 둘 다 0.7과 비교합니다.

if (체력비율 < 0.7) → 체력 구슬 분기
if (마나비율 < 0.7) → 마나 구슬 분기
즉 구슬은 무작위로 떨어지는 게 아니라 문턱 판정입니다. 필요할 때만 나오는 것처럼 느껴지는 이유가 이것입니다. 비교 방향(<)은 판정 헬퍼를 직접 열어 부호 플래그 사용까지 확인했습니다.

「몬스터 → 아이템」 드랍 테이블은 없습니다

찾아봤지만 그런 표 자체가 존재하지 않습니다. 대신 절차적으로 만듭니다.

  1. 등급을 먼저 굴린다 — 위 itemRollQuality
  2. 아이템별 조건으로 거른다 — itemGetMinLevel · itemGetMinRarity · itemGetMinDifficulty · itemGetClass 가 전부 상수 없는 순수 접근자입니다. 조건이 코드가 아니라 아이템 데이터베이스에 항목별로 들어 있다는 뜻입니다
  3. 특수 드랍만 별도 — 예컨대 specificStuffDrop은 중형 마나 물약·대형 체력 물약을 ID로 직접 지정합니다

아이템 DB는 정의 1,584건(itemDataAdd 918 + itemDataAddExt 666)이고 클래스별로 등록됩니다. 필드 구성도 확인했습니다 — 4번 최소 등급 · 5번 최소 레벨 · 6번 클래스.

DB 내용 자체는 못 뽑았습니다. 정의마다 인자가 13개인데 그중 약 40%가 실행 중에 채워지는 메모리를 가리켜 파일에는 값이 없습니다. 완전히 복원하려면 실행 중인 게임 메모리를 읽어야 합니다 — 거기까진 하지 않았습니다.
